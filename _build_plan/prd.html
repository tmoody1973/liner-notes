Liner Notes

Liner Notes turns Radio Milwaukee's airplay history into an explorable artist-influence knowledge graph. An autonomous steward agent cleans and enriches the station's messy playlist data — resolving artists against MusicBrainz, Discogs, and Deezer, and extracting typed artist connections from music journalism via Perplexity — with every dataset, lineage step, and quality check governed in DataHub. Listeners explore "the station's musical brain": influence paths between artists, generated playlists, and a receipts panel showing exactly why every connection exists, with one-tap links out to their own streaming service.

Built for Build with DataHub: The Agent Hackathon (Track 1 — Agents That Do Real Work), on the method of the HDSR Stell-R paper (docs/research/stell-r-artist-influence-hdsr.md), applied to a corpus the paper's authors didn't have: four radio stations' human curation. Ships the first Convex→DataHub ingestion connector as an open-source contribution. The build runs as five milestones, each ending in something visible and testable.

What the app does

  • Convex → DataHub connector

    A recipe-driven Python ingestion source — the first for Convex — that lands both deployments' tables, schemas, and row counts in DataHub. Built to be submitted upstream.

  • Steward agent: resolution & enrichment

    Works the real production backlog — unresolved plays, missing MusicBrainz IDs, ISRCs, labels — in narrated, resumable sessions with auto / LLM-adjudicated / human-review confidence buckets.

  • DataHub write-back

    The agent reads its worklist from DataHub via the MCP Server, then documents every session back: quality assertions, raw→resolved→graph lineage, and plain-English run reports.

  • Influence graph build

    Curation edges from co-play across four stations (the Stell-R method on a new corpus) plus canonical MusicBrainz relationship edges — every edge typed, weighted, station-tagged, and carrying receipts.

  • Editorial edges via Perplexity

    The agent reads music journalism (Pitchfork, AllMusic, Bandcamp Daily, and a configurable registry) through Perplexity's API and extracts typed connections — influenced-by, collaborated-with, compared-to — each with a cited quote as its receipt.

  • Discovery app: explore & traverse

    Graph explorer with station filter, artist-to-artist pathfinder, multi-artist intersections, and coherent generated playlists — with 30-second previews where cached. The paper's four traversal algorithms, made tangible.

  • Liner Notes receipts panel

    The signature: every connection, artist, and playlist track shows why it's there — airplay evidence, canonical source, journalism quote, resolution confidence. Provenance embedded at build time; trust as a visible feature.

  • Streaming links out

    Every track opens in Spotify, Apple Music, Deezer, or YouTube via Odesli — no OAuth, cached lookups, device-remembered preference, graceful search-link fallback.

  • Neighborhoods & bridge artists

    The graph self-organizes into agent-named musical neighborhoods (no genre labels as input); bridge artists get badges and power cross-the-bridge playlists that travel one sound into another.

  • See them live

    Artist pages show upcoming Milwaukee shows (from the platform's existing Ticketmaster/AXS events data) with ticket links; a "live soon" badge follows artists across the app. No new APIs.

Already provided by rm-playlist-v2 (existing production platform, read-only source)

  • Play history across four stations (HYFIN, 88Nine, 414 Music, Rhythm Lab) with real airtime timestamps
  • Partial canonical catalog (artists with some MusicBrainz/Discogs/Spotify IDs; tracks with some ISRCs)
  • An enrichment-status backlog (pending / unresolved plays) — the agent's real work queue
  • Ticketmaster + AXS events with per-event artist joins and a touring-from-rotation view
  • Cached Apple Music 30-second preview URLs and album artwork on tracks

Out of scope (v1)

  • Listener accounts & login — recommendation without user data is the thesis; anonymity is a feature, not a gap.
  • Streaming OAuth (save-to-account) — Odesli deep links deliver the value; OAuth flows are demo risk with zero judging payoff.
  • Audio feature analysis — Spotify's endpoint is deprecated; genre/tag similarity fills the coherence-filter role (a deliberate adaptation from the paper).
  • Native mobile app — responsive web covers the phone experience.
  • Live "now playing" updates — the graph refreshes when the pipeline runs, not the second a song airs.
  • Other organizations / multi-tenant — all four Radio Milwaukee stations are in; other orgs are not.
  • Social features — no sharing buttons, comments, or favorites.
  • Scheduled/autonomous agent runs — sessions start on demand; observable is demoable. Cron is a later config change.
  • Royalty / SoundExchange reporting — a different product; explicitly out so scope can't drift back.
  • Direct scraping of publications — journalism arrives only through Perplexity's cited API; browser automation is a named fallback, not a dependency. JamBase noted as the post-hackathon path to national tour data.

Convex

Data home

Two deployments: rm-playlist-v2 read only (via the streaming export REST API), and a new Liner Notes deployment for resolved data, the graph, and steward records.

  • New Liner Notes project (created at milestone 1)

DataHub

Governance

Runs locally via the official Docker quickstart — the context graph the connector feeds, the MCP Server the agent reads, and the UI where write-back is visible.

Credentials needed

  • None to sign up for — Docker installed; a local access token generated once it's running

MusicBrainz

Canonical IDs

The canonical music knowledge base: artist IDs, relationships (collaborations, memberships), tags, ISRCs. Free and open.

Credentials needed

  • None — just a polite app-identifying user-agent string

Discogs

Cross-check

Release-level detail and a second opinion during entity resolution.

Credentials needed

  • Free personal access token (2-minute signup)

Deezer

Genres & images

Genres, popularity signals, and artist images for enrichment and the coherence filter.

Credentials needed

  • None — public API

Perplexity

Editorial source

Retrieves music journalism about catalog artists with citations — the editorial edge source without scraping. Budget-capped per session.

Credentials needed

  • Perplexity API key (paid; you have an account)

Odesli (song.link)

Streaming links

One lookup per track (seeded by ISRC or existing Spotify/Apple IDs) returns links to it on every major streaming service. Cached.

Credentials needed

  • None required (optional free key raises rate limits)

Milestones

1

Foundation & Connector

Stand up the whole estate: the monorepo, the Liner Notes Convex deployment, DataHub running locally, and the open-source Convex→DataHub connector feeding it — plus a sample dataset so a judge can run everything without Radio Milwaukee's private data.

What gets built

  • Monorepo scaffold (connector / agent / web) with Apache 2.0 license displayed prominently
  • New Liner Notes Convex deployment with the resolved / graph / steward tables
  • Read-only access to rm-playlist-v2 via Convex's streaming export REST API (deploy key)
  • Judge mode: an anonymized sample dataset that seeds the Liner Notes deployment with one command
  • The Python connector: recipe-driven, ingests both deployments' tables with schemas, descriptions, and row counts into a stock DataHub Docker quickstart
  • README with copy-paste setup: DataHub up, deploy keys in, ingest, browse

Not in this milestone

  • The steward agent or any LLM calls
  • Graph building, the web app, editorial or events features
  • Scheduled or continuous connector sync (one-shot runs only)

Done when: from a clean clone, following the README stands up DataHub, seeds the sample data, runs one ingest command, and both deployments' tables are browsable in the DataHub UI with schemas and row counts.

2

Steward Agent

The agent that does real work: narrated sessions that read their worklist from DataHub, resolve and enrich the catalog, route uncertainty to a human review queue, and document everything back into the context graph.

What gets built

  • One-command sessions with live terminal narration of what the agent is checking, matching, and deciding
  • Session start reads DataHub via the MCP Server: current assertions, coverage, prior run reports → prioritized worklist
  • Entity resolution against MusicBrainz with Discogs/Deezer cross-checks — three buckets: auto-apply, LLM-adjudicated (reasoning saved), human review
  • Enrichment: genres/tags, relationships, ISRCs, release years, images — every applied change carrying method, confidence, evidence, and run ID
  • A thin review page: pending matches with their evidence, approve/reject in one click
  • Write-back: updated assertions, raw→resolved lineage, run report as dataset documentation, owners and descriptions set
  • Sessions are idempotent and resumable; source-API-polite

Not in this milestone

  • Graph building or any listener-facing UI
  • Editorial extraction (Perplexity) — milestone 5
  • Hand-editing data in the review page (approve/reject only)
  • Scheduled runs

Done when: a session run against the real backlog resolves artists into the Liner Notes deployment, ambiguous items appear in the review page and can be approved, and the DataHub UI shows refreshed assertions, lineage, and the session's run report.

3

Graph Build

The deterministic pipeline that turns resolved data into the influence graph: curation edges from four stations' co-play, canonical edges from MusicBrainz, neighborhoods, bridge scores, and provenance embedded on everything.

What gets built

  • One-command full graph build/rebuild from resolved data
  • Curation edges: co-play weighting per the Stell-R method, station-tagged, with example show/date receipts
  • Canonical edges from MusicBrainz relationships between catalog artists
  • Neighborhood detection with agent-generated evocative names; bridge scores on every node
  • Provenance embedded into graph tables at build time (the public app never queries DataHub)
  • Readable build summary; the build documented in DataHub with resolved→graph lineage

Not in this milestone

  • Any listener-facing UI (milestone 4 renders this data)
  • Editorial edges (milestone 5 adds the third edge type)
  • Incremental updates — full rebuild per run is the model
  • Any UI for tuning weights or windows (config file only)

Done when: the build completes on resolved data and produces inspectable graph tables — typed, weighted, receipted edges; named neighborhoods; bridge scores — with the build's lineage and summary visible in DataHub.

4

Discovery App

The listener product: the station's musical brain made explorable, with receipts on everything and a door out to the listener's own streaming service.

What gets built

  • Artist search plus featured/most-played entry points
  • Graph explorer: nodes sized by airplay, edges colored by type, station filter chip, tap to re-center; artist panel with image, genres, airplay stats, and 30-second previews where cached
  • Pathfinder: two artists → the hop-by-hop influence path; several artists → intersection discovery
  • Playlist generator with regenerate, stable playlist URLs, and per-track "why this track"
  • Receipts everywhere: connection receipts, artist trust chips, and the "About this data" page
  • Neighborhood map with agent-named districts, neighborhood cards with "start here" playlists, bridge badges, cross-the-bridge playlists
  • Odesli streaming buttons with cached lookups, device-remembered preference, and search-link fallback; fully responsive

Not in this milestone

  • Editorial receipts (the data doesn't exist until milestone 5)
  • See-them-live cards and badges (milestone 5)
  • Full-song playback, accounts, sharing, shareable explorer states

Done when: on a phone browser you can search an artist, explore their neighborhood, find the path between two artists, generate a playlist, read the receipts behind any connection, hear a preview, and open a track in your own streaming service.

5

Editorial, Live & Ship

The third edge type, the real-world bridge, and the submission package: journalism-derived connections with citations, see-them-live, and everything the judges receive.

What gets built

  • Editorial extraction sessions: Perplexity retrieval against the configurable source registry, typed connections with quote + citation + confidence, catalog-artists-only, budget-capped, DataHub-documented
  • Editorial receipts rendered in the app alongside curation and canonical
  • See them live: "On stage near Milwaukee" cards with ticket links, "live soon" badges app-wide, honest "Date TBD" handling
  • Submission package: polished README, sample outputs folder (run reports, generated playlists), verified clean-clone setup, the under-3-minute demo video, upstream connector submission, Devpost text

Not in this milestone

  • Anything from the out-of-scope list (OAuth, JamBase, scraping, scheduling)
  • New feature ideas that arrive during polish — they go to a post-hackathon notes file

Done when: editorial edges with citations appear in the app, live badges show on artists with upcoming Milwaukee shows, the repo passes a clean-clone setup test, and the submission (video, description, sample outputs, license, connector PR) is complete on Devpost.
