# Milestone 3 — Graph Build — log

## What's new in the app

- **The station's musical brain now exists as data.** One command (`npm run graph`) turns the resolved catalog into an influence graph: 360 artists, ~23,000 typed, weighted connections — every one carrying its receipt (how many times two artists were co-played, on which stations, with a real example date; or which MusicBrainz relationship links them).
- **The graph found Milwaukee's musical neighborhoods on its own.** With zero genre labels as input, community detection split the dial into instantly recognizable sounds, and Claude named them like city districts: **Riverwest Basement Circuit** (the local/414 Music scene — Micah Emrich, Holy Pinto, Ellie Jackson), **Bronzeville Groove Society** (the Rhythm Lab neo-soul sound — Thundercat, Erykah Badu, Frank Ocean), **North Avenue Soul Bridge** (contemporary R&B, national + local — Jill Scott, Syd, NILEXNILE).
- **Bridge artists are scored** — the connectors between neighborhoods are all Milwaukee cross-scene artists: Kia Rap Princess, B Free, Amanda Huff, Dana Coppafeel, Troy Tyler. These become the "doorways" the discovery app will highlight.
- **Everything is receipted and inspectable** — the M4 app will be able to show *why* any two artists are connected, down to the timestamped plays.
- The build documents itself in DataHub: lineage now runs raw plays → resolved artists → graph tables, with the plain-English build summary on each graph dataset's page.

## What was built

- **`agent/src/graph/`** (TypeScript, in the agent workspace): `config.ts` (tunables: 60-min window, ≥2 noise floor, scan depth, insert chunking), `coplay.ts` (pure sliding-window co-play pair counting), `build.ts` (orchestrator: load → nodes → edges → Louvain + betweenness → Claude naming → chunked Convex write → DataHub documentation), `naming.ts` (Claude names neighborhoods, deterministic genre fallback with logged reason), `coplay.selfcheck.ts` (known-answer tests, wired into `npm run check`), `verify.ts` (`npm run graph:verify` — independent brute-force recount of sampled edges + canonical edges vs MusicBrainz).
- **`convex/convex/graph.ts`**: `catalogArtists`, chunked `clearGraph` (a full graph is ~23k rows, past Convex's 4096-read mutation limit), `insertNodes/insertEdges/insertNeighborhoods`, `graphStats` (independent count check), `edgeBetween` (pair lookup — feeds M4 receipts panel), `neighborhoodAnchors` (top-spin members per hood — feeds M4 neighborhood cards).
- Dependencies: `graphology`, `graphology-communities-louvain`, `graphology-metrics` (pure JS; loaded via `createRequire` because their CJS `export =` typings fight NodeNext ESM).
- Scripts: `npm run graph [-- --mode=judge]`, `npm run graph:verify`; `npm run check` now runs both self-checks.

## Decisions not pre-specified in the PRD

1. **Stell-R adaptation:** "co-mention in a review" → "co-play within 60 minutes on the same station" (Tarik's call — plays carry no show IDs, and 60 min ≈ the same DJ moment). Edges are **undirected** (co-play has no direction, unlike review mentions); one edge per unordered pair.
2. **Noise floor is mode-aware:** ≥2 co-plays on real data (168k plays), ≥1 in judge mode — the 220-play judge sample produces zero edges under the real floor.
3. **Neighborhood naming vibe:** Milwaukee-flavored evocative district names (Tarik's call), generated by `claude-opus-5` from member artists + genres; deterministic `"{Genre} District N"` fallback keeps the build working without the API.
4. **Bridge score = betweenness centrality** normalized 0–1 over the whole graph (unweighted traversal — co-play weight is similarity, not distance).
5. **Singleton Louvain communities don't become neighborhoods** (≥2 members required); isolated artists keep `neighborhoodId` unset.
6. **Canonical edges dedupe** by unordered pair + relation type; only pairs where both artists are in the catalog (2 today — grows with the catalog).

## Things the next milestone (M4 — discovery app) needs to know

- **Ready-made queries:** `graph:edgeBetween(a, b)` returns the receipted edge(s) for a pair (the receipts panel), `graph:neighborhoodAnchors` returns each hood with top-spin anchor artists (neighborhood cards), `graph:graphStats` for counts.
- **Traversal is M4's job:** Stell-R's algorithms (K-BFS, modified Dijkstra with `1/(w+1)` distance, max-flow, multi-artist intersection) are in `docs/research/stell-r-artist-influence-hdsr.md` Appendix A; the graph tables carry raw weights.
- **Density note:** ~23k edges over 360 nodes is dense. For the explorer UI, filter by weight (receipts carry `coPlayCount`) — e.g. weight ≥ 5 or top-N per node — rather than rendering everything.
- **Rebuild freely:** the graph is a full rebuild (~4 min real mode, seconds in judge mode) and deterministic; rerun after the drain resolves more artists. Names regenerate same-spirit but not verbatim — if a demo needs frozen names, don't rebuild between rehearsal and recording.
- Local artists (no MBID) are first-class nodes; `previewUrl` on tracks is still empty (no audio features by decision).
- Odesli is dead; streaming links come from SonoVault (see MOO-471) — M4 renders `tracks.streamingLinks`.

## Deviations from the PRD

- None in scope. The PRD's "graph added in M3" lineage promise is met: `plays → artists → graphNodes/graphEdges/neighborhoods` in DataHub.
- Environmental: canonical edges number only 2 today because the catalog (~360 artists) rarely contains both ends of a MusicBrainz relation yet; the pipeline picks them up automatically as the backlog drain grows the catalog.
